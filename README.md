# BipMe

BipMe is a creator-specific X distribution-intelligence product. Our first milestone uses one authorized account to validate history ingestion, creator baselines, comparable-post retrieval, Distribution Outlooks, and prediction-versus-outcome monitoring.

**Status:** Repository foundation. No public launch or multi-account scale work is planned.

## Repository

- `apps/api` — Python/FastAPI API, local intelligence modules, SQLAlchemy persistence, and future background worker.
- `apps/web` — React/TypeScript/Vite frontend.
- `docs/adr` — accepted architecture decisions (currently in separate review PRs).
- `docs/research` — source research and design specifications.
- `infra` — local/deployment infrastructure when needed.

## Local setup (foundation)

Requires Python 3.13, [uv](https://docs.astral.sh/uv/), Node 24, pnpm 10, and Docker with Compose.

```bash
docker compose up -d db
cd apps/api
uv sync
uv run alembic upgrade head
uv run uvicorn bipme.api.app:app --reload
```

In a separate shell:

```bash
cd apps/web
pnpm install
pnpm dev
```

Visit the Vite URL shown in the terminal. The frontend displays the API health state.

**Important:** These are foundation scaffolds, not X authentication or intelligence functionality. There are no committed real credentials or creator datasets. Copy `.env.example` into a local untracked `.env` and configure `BIPME_DATABASE_URL` when using migrations.

**Reproducible dependencies:** `apps/api/uv.lock` and `apps/web/pnpm-lock.yaml` were generated by the actual resolvers and committed. CI enforces both locks. Update lockfiles through uv/pnpm when dependencies change.

## Development conventions

Feature and fix branches target protected `main` via PRs; use squash merges. See `AGENTS.md` for coding-agent rules. Do not run live X API requests in CI.
